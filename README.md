# 원흥LH13단지 게스트하우스

게스트하우스 신청·예약을 웹에서 처리합니다. 화면이 목적별로 나뉘어 있습니다.

| 화면 | 누가 | 무엇을 |
|---|---|---|
| `index.html` | 주민 | 신청서를 타이핑해 JPG로 만들어 문자 전송 |
| `draw.html` | 주민 | 신청서를 손으로 써서 JPG로 만들어 문자 전송 |
| `reserve.html` | 주민 | 달력에서 빈 날을 보고 바로 예약 신청 |
| `manage.html` | 관리사무소 | 신청 확인·확정·취소, 신청서 문서 출력 |
| `admin.html` | 관리자 | 서식·요금·계좌·항목 설정 |

**예약(`reserve.html`)은 아직 준비 중입니다.** 자리 잡을 때까지 주민은 기존
타이핑·손글씨 화면을 그대로 씁니다. 예약이 안정되면 그때 정리합니다.

## 신청서 작성 (타이핑·손글씨)

1. 공개 URL에 접속합니다.
2. 성명·동호수·연락처를 입력합니다. 다음부터는 자동으로 채워집니다.
3. 입실일·퇴실일·인원을 고르면 숙박일수와 금액이 자동 계산됩니다.
4. "이미지 만들어 보내기"를 누르면 신청서가 복사된 채 관리사무소 문자 화면이
   열립니다. 입력란을 길게 눌러 **붙여넣기** 한 뒤 보냅니다.
5. "계좌번호 복사"로 입금 계좌를 금융앱에 붙여넣습니다.

입력한 정보는 서버로 전송되지 않고 본인 브라우저에만 저장됩니다.

**왜 붙여넣기를 직접 해야 하나요?** 웹페이지는 문자에 이미지를 자동으로 첨부할
수 없습니다. `sms:` 주소에는 수신자와 본문만 있고 첨부 항목이 자체가 없으며,
반대로 이미지를 넘길 수 있는 공유 시트는 보안상 페이지가 수신자를 지정하지
못하게 막혀 있습니다. 그래서 **번호는 자동으로 채우고 이미지는 클립보드에 담아**
붙여넣기 한 번만 남기는 쪽을 골랐습니다. 번호는 관리자 화면의 *관리사무소 문자
번호*에서 바꾸고, 비워 두면 예전처럼 공유 시트만 열립니다.

클립보드 이미지 복사가 막힌 브라우저(주로 구형 iOS 사파리)에서는 안내를 띄우고
자동으로 공유 시트로 넘어갑니다. PC에서는 문자 앱이 없으므로 언제나 공유 시트를
씁니다.

**"이미지 저장"은 기기에 따라 다르게 동작합니다.** 폰에서는 공유 시트를 열어
'이미지 저장'으로 사진함에 담습니다 — `<a download>`로는 사진함에 들어가지
않기 때문입니다. PC에서는 다운로드 폴더로 바로 내려받습니다. PC에서 저장
위치를 매번 고르고 싶으면 Chrome 설정 → 다운로드 → **"다운로드 전에 각 파일의
저장 위치 확인"**을 켜세요.

## 예약 (`reserve.html`)

1. 달력에서 입실일과 퇴실일을 차례로 누릅니다. 날짜마다 예약할 수 있는
   자리 수가 표시됩니다.
2. 성명·동호수·연락처·인원을 넣고 "예약 신청"을 누릅니다.
3. 관리사무소가 입금을 확인하면 확정됩니다. 이 화면을 다시 열면 진행 상태가 보입니다.
   **어느 곳을 쓰는지는 확정된 뒤에 표시됩니다** — 배정은 관리사무소가 정합니다.

확정 전까지는 본인이 취소할 수 있습니다. 확정된 예약은 관리사무소에 연락해야 합니다.

**개인정보 안내.** 예약 신청 정보(성명·동호수·연락처)는 관리사무소 확인을 위해
저장되며 관리사무소만 열람합니다. 달력에는 예약 여부만 표시되고 다른 주민의
이름·연락처는 보이지 않습니다. 이 구분은 안내 문구가 아니라 데이터베이스가
강제합니다 — 주민 화면이 쓰는 키로는 예약자 정보를 조회할 권한 자체가 없습니다.

## 금액 계산 기준

- 월~목: 1박 35,000원 / 금·토·일: 1박 40,000원
- 기준 2인, 3인부터 1박당 1인 5,000원 추가
- 공휴일과 **공휴일 전날 밤**도 40,000원입니다. 한국천문연구원 특일정보 API로
  자동 판별하므로 따로 체크할 것이 없습니다.
- 금액은 자동 계산이며 직접 고칠 수 없습니다. 최종 확인은 관리사무소(031-965-7502) 기준입니다.

## 예약 제한

- 오늘부터 **한 달 이내**의 날짜만 고를 수 있습니다.
- 한 번에 **최대 2박**입니다. 퇴실일은 입실일 다음날부터 이틀 뒤까지만 열립니다.

위 금액·기준·제한은 모두 초기값이며 관리자 페이지에서 변경할 수 있습니다.

## 관리자

`admin.html`에서 요금·계좌·입력 항목·칸 위치를 바꿉니다.

1. `manage.html`과 **같은 계정**으로 로그인합니다. 예약 확인 화면에서 이미
   로그인했다면 그대로 넘어가면 됩니다.
   **로그인하기 전에는 편집 화면이 아예 열리지 않습니다** (`manage.html`과 같습니다).
2. 값을 고치고 "미리보기 & 저장" 탭에서 실제 화면을 확인한 뒤 저장합니다.
3. **반영까지 최대 10분쯤 걸립니다.** 저장은 즉시 되지만, 주민 화면에 쓰이는
   `config.json`은 5분마다 도는 동기화 작업이 갱신합니다.
4. 잘못 저장했다면 "되돌리기"에서 이전 설정을 불러옵니다.

직원 계정은 Supabase Authentication → Users에서 추가합니다(아래 예약 시스템
설정 절과 같습니다). **예약 확인과 설정 변경은 같은 권한입니다** — 로그인할 수
있는 사람은 요금과 계좌도 바꿀 수 있습니다.

로그인 세션은 한 시간쯤 지나면 만료됩니다. 칸 위치를 잡다 보면 그보다 오래
걸리는데, **만료돼도 고치던 내용은 그대로 남습니다.** 다시 로그인하면 편집
화면이 그 상태로 돌아오고 이어서 저장하면 됩니다. 로그아웃도 마찬가지입니다 —
화면을 닫는 것이지 편집을 버리는 것이 아닙니다(탭을 닫으면 사라집니다).

### 설정의 원본은 Supabase입니다

`config.json`은 자동으로 만들어지는 **사본**입니다. 저장소에서 직접 고치면
다음 동기화가 덮어씁니다. 값을 바꾸려면 `admin.html`을 쓰세요.

이렇게 나눈 이유는 주민 화면이 Supabase를 몰라도 되게 하기 위해서입니다.
Supabase가 멈춰도 신청서·예약 화면은 정적 `config.json`으로 정상 동작합니다.
`config.json`이 없거나 깨져도 신청서는 `config.js`의 내장 기본값으로 동작합니다.

### 서식 이미지 교체 (관리자 전용)

서식 이미지를 바꿀 때만 GitHub 토큰이 필요합니다. `admin.html`의 "서식 이미지
교체" 항목을 펼치면 나옵니다. 요금·계좌·항목만 고칠 때는 로그인만으로 충분합니다.

토큰은 Settings → Developer settings → Personal access tokens → Fine-grained
tokens 에서 이 저장소 하나만 선택하고 **Contents: Read and write** 권한만 주어
만듭니다. 공용 PC에서 썼다면 반드시 "토큰 삭제"를 누르세요.

### 잠겼을 때 복구하기

`admin.html`에서 예약 기능의 주소·키를 잘못 저장하면 Supabase에 못 붙어 다시
고칠 수 없게 됩니다. 로그인도 그 주소로 하므로 **화면 자체가 안 열립니다.**
저장 전에 검증하므로 웬만해선 막히지만, 그래도 막혔다면:

1. Supabase SQL Editor에서 `app_config`를 직접 고칩니다. **이것이 정석입니다.**

   ```sql
   update app_config set config = jsonb_set(config, '{reservation,url}', '"https://올바른주소"') where id = 1;
   ```

2. 그것도 막혔으면 저장소의 `config.json`을 직접 고칩니다. 주민 화면은 즉시
   복구되지만 다음 동기화가 다시 덮어쓰므로 **1번을 반드시 해야 합니다.**

## 관리사무소 (`manage.html`)

주민 예약을 확인하고 확정·취소합니다.

1. 이메일·비밀번호로 로그인합니다. 한 번 하면 유지됩니다.
2. "확인 필요" 목록에서 입금을 확인하고 **확정**을 누릅니다.
3. 종이 서식이 필요하면 **신청서** 버튼으로 이미지를 받습니다.
4. 잘못된 신청은 **취소**를 누르면 달력에서 자리가 풀립니다.
5. 필요하면 **배정 변경** 버튼으로 다른 곳으로 옮깁니다. 그 기간에 이미 차 있으면
   거부됩니다. 확정 후에 옮겼다면 주민에게 따로 알려 주세요 — 화면에는 바뀐 값이
   보이지만 이미 안내받은 주민은 다시 확인하지 않을 수 있습니다.

화면은 탭 셋으로 나뉩니다. 기본은 "확인 필요"라 탭을 누르지 않으면 예전과 똑같습니다.

| 탭 | 무엇을 |
|---|---|
| 확인 필요 | 대기 신청과 확정된 예약. 확정·취소·신청서 출력 |
| 달력 | 이번 달 일정을 한눈에. 날짜를 누르면 그날 예약이 펼쳐집니다 |
| 지난 예약 | 세대(동·호)나 이름으로 지난 예약 찾기 |

각 신청 카드에는 그 세대의 **최근 6개월 이용 이력**이 함께 표시됩니다. "이력 보기"를
누르면 지난 예약이 펼쳐집니다. 이용 횟수 제한은 없으므로 참고용 숫자입니다.

금액은 저장된 값과 함께 요금표로 다시 계산한 값을 보여줍니다. 다르면 빨간
경고가 뜹니다 — 주민 브라우저가 보낸 값이라 그대로 믿지 않습니다. 공휴일 요금이
반영된 정상 차이일 수도 있으니 사람이 판단합니다.

은행입금일은 신청서에 비어 있습니다. 입금 확인 후 직접 적는 칸입니다.

## 예약 시스템 설정 (Supabase)

예약은 서버가 필요합니다. Supabase 무료 티어를 씁니다.

1. Supabase 프로젝트를 만듭니다. Region은 **Northeast Asia (Seoul)**.
   Security에서 "Automatically expose new tables"는 **끕니다**.
2. `docs/superpowers/plans/2026-07-29-guesthouse-reservation-stage1.md`의
   Task 1에 있는 SQL을 SQL Editor에 붙여넣고 실행합니다.
3. 같은 문서의 확인 쿼리로 중복 방지가 동작하는지 봅니다.
   **겹치는 예약이 실패해야** 정상입니다.
4. Authentication → Users에서 관리사무소 계정을 만듭니다(Auto Confirm User 켜기).
5. `docs/superpowers/plans/2026-08-06-admin-login.md`의 Task 1 SQL을 실행해
   설정 원본 테이블 `app_config`를 만들고 현재 `config.json`으로 시딩합니다.
   **정책(policy)만이 아니라 `grant`까지 함께 실행해야 합니다** — 1번에서 자동
   노출을 껐기 때문에 새 테이블에 권한이 자동으로 붙지 않습니다.
6. Settings → API에서 Project URL과 **anon public** 키를 복사해
   `admin.html`의 "요금 · 계좌" 탭 → "예약 기능"에 넣고 스위치를 켭니다.

**`service_role` 키는 쓰지 않습니다.** 그 키는 권한 제한을 통째로 무시합니다.

`admin.html`에 들어갔을 때 **"저장된 설정을 불러오지 못했습니다"** 토스트가 뜨면
5번이 빠진 것입니다. 브라우저 개발자도구 Network 탭에서 `app_config` 요청을 보면
`PGRST205`(테이블 없음)인지 `42501`(권한 없음)인지 구분됩니다. 앞이면 테이블
생성부터, 뒤면 `grant`만 실행하면 됩니다.

무료 프로젝트는 한 주 동안 접속이 전혀 없으면 일시정지됩니다. 그러면 Supabase
대시보드에서 Restore를 눌러 살려야 합니다.

## 사용량 알림 (텔레그램)

주민이 신청서 이미지를 만들 때마다 숫자가 1 오르고, 매일 아침 7시 반쯤 어제 건수가
텔레그램으로 옵니다.

```
📋 8월 4일 신청서 3건
   타이핑 2 · 손글씨 1
```

**세는 것은 이미지가 만들어진 횟수입니다. 신청 세대 수가 아닙니다.** "보내기"가
실패해서 "저장"을 다시 누르면 2로 셉니다. 세대별로 합치려면 이름·동호수를 서버로
보내야 하는데, 그러면 개인정보가 텔레그램까지 흘러갑니다. 숫자가 조금 부풀더라도
아무것도 안 보내는 쪽을 택했습니다.

**서버에 저장되는 것은 날짜와 숫자 두 개뿐입니다.** 누가 언제 무엇을 신청했는지는
저장되지 않습니다.

### 준비

1. `docs/superpowers/plans/2026-08-05-usage-telegram.md`의 Task 1 SQL을 Supabase
   SQL Editor에서 실행합니다.
2. 텔레그램 **@BotFather** 에게 `/newbot` 으로 봇을 만들고 토큰을 받습니다.
3. 알림 받을 방에 봇을 초대하고 아무 메시지나 보낸 뒤,
   `https://api.telegram.org/bot<토큰>/getUpdates` 에서 `chat.id`를 확인합니다.
   그룹이면 음수입니다.
4. 저장소 Settings → Secrets and variables → Actions 에 `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_CHAT_ID`를 등록합니다.
5. Actions 탭 → "일일 사용량 알림" → **Run workflow** 로 한 번 눌러 확인합니다.

알림이 며칠째 안 오면 Actions 탭에서 빨간불을 확인하세요. 0건인 날도 메시지가
오도록 만들었으므로 **아무것도 안 오는 것은 고장입니다.**

**하루치만 통째로 빠졌다면** 대개 GitHub이 그날 예약 실행을 건너뛴 것입니다.
예약 워크플로는 보장된 스케줄이 아니라 여유가 있을 때 돌려주는 것이라, 부하가
높으면 늦어지거나 아예 생략됩니다. 2026-08-06분이 이렇게 누락돼 실행 시각을
정시에서 37분으로 옮겼습니다(정시는 전 세계 cron이 몰리는 시간대입니다).
급하면 Actions 탭 → **Run workflow** 로 직접 보낼 수 있습니다 — 어제 날짜를
스스로 계산하므로 아침에 누른 결과와 같습니다. 이게 반복되면 GitHub Actions
대신 Supabase `pg_cron`으로 옮기는 편이 낫습니다.

**빨간불도 없고 실행 기록이 며칠째 없다면** 워크플로가 Disabled 상태인지 확인하세요.
GitHub은 60일 동안 커밋이 없는 저장소의 예약(`schedule`) 워크플로를 자동으로
끕니다. 이 사이트는 설정이 안정되면 몇 달씩 커밋이 없을 수 있어 실제로 걸릴 수
있는 조건입니다. Actions 탭에서 워크플로를 열어 다시 켤 수 있습니다. 이 알림이
멈추면 매일 아침 실행되던 Supabase 접속도 함께 끊겨, 이 워크플로가 덤으로
막아주던 일시정지 방지(위 "한 주 동안 접속이 없으면 일시정지" 항목)까지 같이
멈춘다는 점을 기억하세요 — 방치하면 예약 기능 자체가 죽습니다.

봇 토큰은 저장소 Secrets에만 있습니다. 주민 브라우저에는 들어가지 않습니다 —
들어가면 누구나 그 토큰으로 채팅방에 아무 메시지나 보낼 수 있습니다.

## 설정 구조

| 파일 | 역할 |
|---|---|
| `config.json` | Supabase `app_config`의 자동 생성 사본 · 주민 화면(`index`·`draw`·`reserve`·`manage`)이 실제로 읽는 데이터 |
| `config.js` | 내장 기본값 · 검증/정규화 · 좌표 변환 · 배치 규칙 · `derive()` |
| `github.js` | GitHub Contents API 래퍼 |
| `reservations.js` | 달력 가용성 계산 · Supabase 호출 |
| `usage.js` | 신청서 생성 건수 집계 호출 |
| `device.js` | 폰·PC 판별 (저장을 공유 시트로 할지 다운로드로 할지) |
| `configstore.js` | Supabase에 저장된 설정 원본을 읽고 쓰기 |

서식 칸의 좌표는 사각형(`rect`) 하나로 저장하고, `index.html`은 중심점으로
변환해 쓰고 `draw.html`은 사각형 그대로 씁니다. 관리자는 칸을 한 번만 잡으면 됩니다.

항목(`fields`)의 `input` 값이 화면에서의 모습을 정합니다.

| `input` | 화면 |
|---|---|
| `text` / `phone` | 한 줄 입력. `charset`으로 한글만·숫자만 제한 가능 |
| `date` | 커스텀 달력 팝오버 |
| `unit` | 동 목록 + 호 입력 두 칸. 서식에는 `1301동 1201호`처럼 한 줄로 찍힘 |
| `choice` | 인원 선택 버튼 |
| `readout` | 자동 계산 표시칸 (사용일수·사용금액). 고칠 수 없음 |
| `null` | 화면에 칸이 없고 서식에만 찍힘 (사용기간) |

`rect`가 `null`이면 화면에만 있고 서식에는 안 찍힙니다(입실일·퇴실일).
반대로 `input`이 `null`이면 서식에만 찍힙니다(사용기간).

`unit` 항목의 동 목록은 `dongStart`~`dongEnd`(기본 1301~1316)를 펼쳐서 만듭니다.
관리자 화면의 **동 시작 번호 / 동 끝 번호**를 고치면 신청서·예약 신청·내 신청
조회·관리자 세대 검색 네 화면의 목록이 함께 바뀝니다. 단지에 없는 동이나
오타가 신청서에 찍히지 않도록 직접 입력 대신 목록에서 고르게 했습니다.

## 개발

```bash
node --test calc.test.mjs config.test.mjs github.test.mjs reservations.test.mjs wiring.test.mjs usage.test.mjs notify.test.mjs device.test.mjs configstore.test.mjs syncconfig.test.mjs
python -m http.server 8000  # 로컬 확인 (file://로 열면 이미지 저장이 실패합니다)
```

`wiring.test.mjs`는 `reserve.html`·`manage.html`에서 id가 붙은 버튼이 실제로
리스너에 연결됐는지 정적으로 확인합니다. 함수를 만들어놓고 버튼에 연결하지 않아
눌러도 아무 일도 일어나지 않던 사고가 있어 추가했습니다.
