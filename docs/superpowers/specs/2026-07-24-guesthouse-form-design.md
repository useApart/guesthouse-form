# 게스트하우스 신청서 자동 작성 웹앱 설계

작성일: 2026-07-24

## 배경

원흥LH13단지 게스트하우스 신청서(`게스트 하우스 신청서.jpg`, 707×1000)를 이용할 때마다
손으로 작성하는 것이 번거롭다. 서식은 고정이고 실제로 바뀌는 칸은 8개뿐이므로,
웹에서 값을 입력하면 완성된 JPG를 생성해 문자(MMS)로 첨부해 보낼 수 있게 한다.

작성자 본인뿐 아니라 같은 단지 주민 누구나 쓸 수 있어야 한다.

## 목표

- 폰(iOS/Android) 및 PC 브라우저에서 동작
- 값 입력 → 원본 서식과 동일한 모양의 JPG 생성
- 생성된 JPG를 문자에 첨부 가능 (공유시트 또는 다운로드)
- 방문자는 계정·설치 없이 URL만으로 사용

## 비목표 (YAGNI)

- 로그인, 회원가입, 사용자 계정
- 서버, 데이터베이스, 신청 이력 조회
- 관리사무소로의 자동 전송/제출
- 결재란(매니저/팀장/센터장) 입력 — 담당자 몫이므로 공백 유지
- PDF 출력, 인쇄 최적화

## 아키텍처

서버가 없는 **정적 파일 3개**. GitHub Pages에 그대로 올리면 앱이 된다.

| 파일 | 책임 |
|---|---|
| `index.html` | 화면·입력 폼·canvas 렌더링·공유. CSS/JS 인라인 |
| `calc.js` | 요금·숙박일수 계산 (순수 함수, DOM 의존 없음) |
| `form.jpg` | 원본 서식 이미지 |

계산 로직만 `calc.js`로 분리하는 이유는 **테스트 가능성**이다.
DOM에 얽힌 코드는 검증이 어렵지만, 순수 함수는 `node --test`로 즉시 검증할 수 있다.
금액 계산은 이 앱에서 유일하게 "틀릴 수 있는" 로직이므로 여기에만 자동 테스트를 붙인다.

서식 이미지는 data URI로 인라인하지 않고 별도 파일로 둔다.
base64는 용량이 33% 늘고 `index.html`을 사람이 읽을 수 없게 만든다.
동일 출처에서 로드되므로 canvas가 오염되지 않아 `toBlob`이 정상 동작한다.

> 로컬 확인 시에는 `file://`로 열지 말 것. 브라우저가 canvas를 오염된 것으로 간주해
> `toBlob`이 실패한다. `python -m http.server`로 띄워서 확인한다.

```
[입력 폼] --(실시간)--> [<canvas>: 배경 JPG + 좌표별 fillText] --> toBlob('image/jpeg')
                                                                    |
                                                    +---------------+---------------+
                                                    |                               |
                                          navigator.share (폰)            <a download> (PC/폴백)
```

### 왜 canvas 직접 렌더링인가

- 원본 JPG를 그대로 배경으로 깔기 때문에 서식이 원본과 100% 동일하다.
  HTML로 표를 재현하면 미묘한 차이가 생기고 유지보수 부담이 크다.
- html2canvas 같은 외부 라이브러리가 불필요하다. 의존성 0.
- 출력 해상도는 원본과 동일한 707×1000, JPEG 품질 0.92.
  업스케일하면 배경이 뭉개지고, MMS 첨부 용량에도 불리하다.

### 데이터 보관

입력값은 `localStorage`에만 저장한다. 서버가 없으므로 개인정보가 외부로 나가지 않고,
사용자 간 데이터가 섞이지 않는다.

- 저장 대상: 성명, 동·호수, 연락처 (매번 동일한 값)
- 저장하지 않음: 날짜, 인원, 금액 (매번 다름)

## 화면 구성

세로 1페이지. 위쪽이 입력 폼, 아래쪽이 실시간 미리보기(canvas). 입력할 때마다 즉시 갱신된다.

### 입력 필드

| 서식 칸 | 입력 방식 | 비고 |
|---|---|---|
| 신청일 | date | 오늘 날짜 기본값, 수정 가능 |
| 성명 | text | localStorage 자동 복원 |
| 동·호수 | text | localStorage 자동 복원 |
| 연락처 | tel | localStorage 자동 복원 |
| 사용기간 | date 2개 (입실일/퇴실일) | 서식에는 `M/D~M/D` 형태로 렌더 |
| 숙박일수 | 자동 산출 | 퇴실일 − 입실일, `N박` 표기 |
| 사용인원 | select 2~4 | 운영규정상 최대 4인 |
| 사용금액 | 자동 계산 + 직접 수정 가능 | 천 단위 콤마, `원` 붙여 렌더 |

### 금액 계산 규칙

1박 단위로 계산한다. 입실일부터 퇴실 전날까지 각 "밤"에 대해:

- 그 밤의 요일이 **금·토·일이면 40,000원**, 그 외(월~목)는 **35,000원**
- 기준 인원 2인. 3인부터 **추가 1인당 1박에 5,000원** 가산

> **미확정 사항:** 원문 "추가 인원 1인당 5,000원의 추가 요금이 발생합니다"는
> 1박당인지 전체 1회인지 명시되어 있지 않다. 관리사무소 확인 전까지 **1박당**으로 계산한다.
> 사용금액 필드가 직접 수정 가능하므로 틀려도 사용에 지장이 없으며,
> 확인 후에는 상수 한 곳만 고치면 된다.

공휴일 요금(공휴일 전날~공휴일 40,000원)은 매년 날짜가 바뀌어 자동 판별이 어렵다.
**"공휴일 요금 적용" 체크박스**를 두어 사용자가 해당 숙박에 수동 적용한다.
자동 계산은 어디까지나 편의이며, 최종 금액은 사용자가 확정한다.

## 렌더링 좌표

707×1000 좌표계. 표의 격자선을 픽셀 스캔으로 실측해 확정했다.

- 신청자 블록 가로선: y = 196, 226, 255, 285, 314 / 값 칸 세로선: x = 229 ~ 636
- 사용 블록 가로선: y = 321, 353, 386 / 세로선: x = 70, 230, 372, 485, 636

각 칸의 중앙에 텍스트를 그린다.

| 필드 | 중심 x | 중심 y |
|---|---|---|
| 신청일 | 432 | 211 |
| 성명 | 432 | 241 |
| 동·호수 | 432 | 270 |
| 연락처 | 432 | 300 |
| 사용기간 | 301 | 337 |
| 숙박일수 | 560 | 337 |
| 사용금액 | 301 | 370 |
| 사용인원 | 560 | 370 |

첫 결과물 확인 후 1~2px 미세조정은 있을 수 있다.

폰트는 canvas 기본 sans-serif 계열을 지정하되, OS별 한글 폰트 차이를 감안해
`"Malgun Gothic", "Apple SD Gothic Neo", sans-serif` 순으로 폴백한다.
칸 너비를 넘는 텍스트는 `measureText`로 감지해 폰트 크기를 축소한다.

## 출력·공유

1. `canvas.toBlob(..., 'image/jpeg', 0.92)`
2. `navigator.canShare({files})`가 참이면 `navigator.share`로 공유시트 호출
   → 사용자가 문자 앱을 선택해 첨부
3. 미지원 환경(주로 데스크톱)은 `<a download>`로 파일 저장
4. 파일명: `게스트하우스신청서_YYYYMMDD.jpg`

## 입금 정보 복사

서식 이미지에 계좌번호가 인쇄되어 있지만, 폰에서 이미지의 숫자를 금융앱에 옮겨 적는 것은 번거롭다.
페이지 하단(생성 버튼 옆)에 탭 한 번으로 클립보드에 복사되는 영역을 둔다.

| 버튼 | 복사되는 값 | 이유 |
|---|---|---|
| 계좌번호 복사 | `85690100129046` | 하이픈 없는 숫자만. 금융앱 붙여넣기 시 하이픈을 거부하는 경우가 있다 |
| 금액 복사 | `70000` | 콤마·`원` 없는 숫자만. 이체금액 입력란에 그대로 들어간다 |

화면에는 사람이 읽을 수 있게 `국민 856901-00-129046 / 원흥LH13단지주거복지지원센터`를 함께 표시한다.
복사 후에는 버튼 라벨을 잠시 "복사됨"으로 바꿔 피드백을 준다.

`navigator.clipboard`를 쓰되, 비보안 컨텍스트나 미지원 브라우저에서는
임시 `<textarea>` + `document.execCommand('copy')`로 폴백한다.
(GitHub Pages는 HTTPS이므로 정상 경로로 동작한다.)

계좌 정보는 서식 이미지와 동일한 값을 코드에 상수로 둔다. 이미지에서 읽어오지 않는다.

## 에러 처리

- 필수값 누락 시 생성 버튼 비활성화 + 어떤 칸이 비었는지 표시
- 퇴실일이 입실일보다 빠르면 경고, 계산 중단
- 숙박 5박 초과 시 경고 표시 (운영규정: 1세대 한 달 기준 5박 이상 불가)
- `navigator.share` 실패/취소는 조용히 무시하고 다운로드 버튼을 노출

## 검증 방법

### 자동 테스트 — `calc.js`

외부 테스트 프레임워크는 설치하지 않는다. Node 내장 `node --test`로 충분하다.

| 케이스 | 기대값 |
|---|---|
| 평일(월~목) 2박 2인 | 70,000 |
| 금·토 2박 2인 | 80,000 |
| 목·금 2박 4인 | 35,000 + 40,000 + (2인 × 5,000 × 2박) = 95,000 |
| 공휴일 요금 적용 2박 2인 | 80,000 |
| 퇴실일 ≤ 입실일 | 숙박일수 0, 금액 0 |

### 수동 확인

UI와 이미지 렌더링은 "눈으로 맞는가"가 판단 기준이므로 수동으로 확인한다.

1. `python -m http.server`로 띄워 각 칸의 글자가 격자 안에 들어가는지 확인
2. 생성된 JPG를 실제 문자로 전송해 수신 측에서 판독 가능한지 확인
3. iOS Safari / Android Chrome 각각에서 공유시트 동작 확인
4. 계좌번호 복사 후 금융앱에 붙여넣기가 되는지 확인

## 배포

GitHub Pages. 공개 저장소에 `index.html` 하나를 두고 Pages를 활성화한다.
방문자는 계정 없이 URL 접속만으로 사용한다.
수정이 필요하면 파일을 갈아끼우고 push하면 즉시 반영된다.

배포 전 로컬에서 브라우저로 열어 동작을 확인한다.
